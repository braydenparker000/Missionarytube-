# Claude Player — architecture and fidelity plan (for review)

**Objective (fixed):** a faithful, independently written browser recreation of **Poweramp build 1031**:
its screen hierarchy, built-in appearance configurations, controls, library, settings, gestures,
animation relationships, waveform, EQ and queue. It is not a new player inspired by Poweramp.
**Status:** this is the original plan, written before implementation. The implementation now
exists in `frontend/claude-player/`; the [coverage matrix](coverage-matrix.md) (Build column, section
5) and the [research notebook](research-notebook.md) (build status per finding) record what is
built. Deployment needs the owner's approval.

## 2. How reference fidelity is achieved (the core idea)

The research found that Poweramp's UI is **generated by a declarative system**, not drawn screen by
screen:

1. A **theme composer** (F10): base skin style + ordered options. Each option applies an overlay
   style, possibly re-pointed by an earlier option.
2. A **single scene graph** (F02–F04): one container, about 25 top-level elements, each with
   parameters per named scene (`scene_playing`, `scene_lib`, …) and per transient state.
3. A **one-pass constraint layout** (F09) whose dimensions come from **window-size buckets** (F12).
4. A **scene clock** (F05–F07): a quartic ease-out, a velocity-shortened duration, interruption from
   the current ratio, and asymmetric declared times.
5. A **message bus** (F02) connecting buttons to the player service.

Fidelity therefore comes from **reproducing those five mechanisms in original code** and feeding them
an **authored reference specification**. This is our own data file, built element by element, with a
citation (resource name and build) on every value. That's better than tuning CSS until a screenshot
looks right. The same option change then produces the same geometry change the reference produces,
for every configuration, instead of the few we happened to screenshot.

Rules that keep this honest:
- **Spec values are functional parameters only**: dimensions, durations, alphas, scale, scene
  membership, constraint relations, colour values. No drawables, vector paths, fonts or long strings
  are carried over. Icons are drawn originally to match the measured size, weight and position.
- **Every spec value has a status** (`CS`/`CR`/`INF`/`OPEN`). Prototype code may use a provisional
  value for an `OPEN` item only when it is visibly labelled in the diagnostics overlay and listed in
  the coverage matrix.
- **No equivalence claim without comparative evidence** (see §6). Static conformance is not runtime
  fidelity.

## 3. Architecture options and selection

| | A. Reference-model scene engine (hybrid DOM + targeted canvas) | B. Framework app (Svelte/React), route-per-screen, CSS/WAAPI transitions | C. Full-scene immediate-mode Canvas/WebGL (CanvasKit-like) |
| --- | --- | --- | --- |
| Mirrors F02–F05 | Directly: same scene/param/clock model | Poorly: shared elements across scenes, mid-ratio reversal and velocity durations become bespoke per transition | Yes, but text, input and accessibility must be rebuilt |
| Text, i18n/RTL, marquee, IME, a11y | Native DOM | Native DOM | Re-implemented; weak |
| Per-frame cost | Transforms/opacity on ~25 elements; solver only for `dynamic` subtrees | Framework reconciliation and style recalc per frame | Full raster per frame |
| Build/hosting fit | Native ES modules, no compile step, no infra change | Needs a compile step: commit generated output (against repo rules) or change the build | WASM/runtime ≈2+ MB against 4.47 MiB headroom |
| Measured (F24, 8× CPU throttle, synthetic) | **59.7 fps, 0 % frames >33 ms**; list 60 fps | Not separately measured (shares DOM cost plus framework overhead) | **15 fps, 98.7 % >33 ms**; canvas list 22.7 fps |

**Selection: A.** Rendering split: retained DOM views positioned by our solver and animated by one
`requestAnimationFrame` scene clock writing only `transform`/`opacity`. Canvas 2D for Waveseek, EQ
curves, knobs and the frequency-response scroller. WebGL only for visualization and, if profiling
demands it, the art backdrop blur. No UI framework: the reference is a retained custom-view system,
and a small retained view layer is the closest analogue.

**Discriminating experiment, already run** (F24, [`experiments/renderer-bench`](experiments/renderer-bench/)):
full-scene canvas loses decisively, and DOM compositor-only and DOM layout-per-frame both hold 60 fps
for ~15 elements. **Next discriminator, inside M1:** can a one-pass solver reproduce the reference
geometry? Pass: every element rect is within ±0.5 dp of an independently computed oracle in 3 buckets
× 2 scenes × 2 skins. Fallback if it fails: per-bucket precomputed rect tables for the failing elements
(still reference-derived, but less general), recorded as a limitation.

## 4. Application decomposition

```
frontend/claude-player/
  index.html                 shell, CSP meta, viewport-fit=cover
  src/model/                 qualifiers.js (bucket resolver), theme.js (ThemeComposer), spec/ (authored reference spec + citations)
  src/scene/                 fastlayout.js (one-pass solver), scene-engine.js (SceneParams, baseScene, recalcChildren), clock.js (SceneClock, StateAnimClock, animScale)
  src/views/                 retained view classes mirroring reference widgets: AlbumArt, Waveseek, PlayPause, Elapsed, Duration, TrackLabels, SubAAButtons, Navbar, VirtualList, ListScroller, …
  src/input/                 gesture-arena.js (ownership, axis lock, cancel, click-through), recognisers (tap, long press, h/v swipe, pinch)
  src/bus/                   message-bus.js (command ids mirroring msgId semantics)
  src/audio/                 playback-service.js (wanted vs confirmed state), media-session.js, graph.js (optional Web Audio DSP), waveform-worker.js
  src/library/               index-worker.js (tags, categories, sort keys), adapters/local-files.js, adapters/synthetic.js
  src/settings/              schema.js (typed, defaults, dependencies, status per key), store.js (versioned IndexedDB, corruption/denial handling)
  src/icons/                 original SVG sprite
  fonts/                     OFL Manrope subset, licensed Bold substitute
```

- **Presentation/scenes:** the scene engine owns geometry and alpha. Views own their content and
  never position themselves.
- **Input:** `GestureArena` assigns one owner per pointer from `pointerdown` until `pointerup`/
  `pointercancel`. It arbitrates axes against native vertical list scroll (`touch-action`), makes
  outgoing scene elements inert during transitions, swallows the click after any owned drag, cancels
  on a second pointer, and honours keyboard/focus and reduced motion.
- **Settings:** one typed schema covering all 452 reference keys with defaults, ranges and
  dependencies (F17). Each key carries an implementation status. The schema is versioned with
  migrations. On corruption: back up, reset and notify. On storage denial: run in memory with a
  banner. Storage uses only the `claude-player:` namespace.
- **Audio:** wanted state (user intent), confirmed state (media events) and position (media clock)
  are separate. Play promises carry a request token, so a stale resolve cannot resume. There is no
  auto-resume after errors or interruptions unless a setting says so. Two media elements allow fades.
  An optional Web Audio graph (biquad bank, preamp, dynamics limiter, convolver) is enabled only when
  EQ is on, and its effect on background playback is measured on device before it becomes the default.
- **Catalog/sources:** a worker builds category indexes (albums, artists, album artists, genres,
  composers, years, folders) from tags with the reference sort rules (articles, album-artist options).
  The local source uses a file picker; on Android Chrome, file access ends with the session. After a
  reload, tracks are marked “needs re-pick” with honest provenance. Optional OPFS import is an explicit
  user choice showing the quota. Remote/catalog adapters come later and only through existing public
  contracts, with no backend changes.

## 5. Android/web limitations stated up front

`UNSUPPORTED_WEB`: bit-perfect/Hi-Res/DAC output, output and resampler selection, DVC, buffer and
audio-focus policies, headset-plug or Bluetooth-connect auto-resume, volume-key skipping, Poweramp's
own lock screen (OS media notification only), widgets, the quick-settings tile, Android Auto,
Chromecast, persistent folder access and rescans, tag writing and file deletion, Material You system
palette, launcher-icon choice, 3rd-party skin APKs, and AutoEQ within the budget. `LEGAL`
substitutes: the TT Norms Pro default font, all icons and drawables, and visualizer presets pending
review. Browser window buckets differ from app window buckets (F12). The plan makes the basis explicit
and recommends evaluating in standalone/full-screen mode.

## 6. Fidelity verification

1. **Static conformance (automated, every slice).** A separate research script
   (`scripts/claude-player/reference-oracle.py`) reads a locally decoded APK directory supplied at run
   time and computes expected element rects, scene params and timings per bucket. Small expected-value
   fixtures, each with a citation header, are committed under `tests/claude-player/fixtures/`. The JS
   solver must match them. This shows we implement the model as read; it doesn't show the model is right.
2. **Runtime correspondence (owner device, needed for `CR`).** A capture protocol per milestone:
   screenshots of named configurations and states, plus 60/120 fps screen recordings of named gestures
   on the owner's phone running build 1031. Frames are analysed in scratch with ffmpeg (element position
   vs time, curve fit against F05). If adb is available, `uiautomator dump` view bounds are captured too.
   Results promote items to `CR` or open defects.
3. **Paired visual review.** The same configuration, state and window basis, side by side and
   overlaid. Differences are recorded, never hidden. The owner's blind A/B evaluation stays separate
   and later.

## 9. Decisions and risks for the owner

1. **Repository incident: the APK reached a public branch.** The upload commit `4003013` (ZIP containing
   the APK) was on public branch `claude/vigilant-galileo-l7udmo` for ~15 minutes. It was removed by
   resetting the branch to `main`. GitHub can still serve an unreferenced commit by its SHA until it
   garbage-collects it. To purge it fully, ask GitHub Support to remove the cached commit.
2. **IP posture.** The plan reproduces behaviour, structure and functional parameters, never
   proprietary assets, code, fonts or presets. Close visual fidelity of a commercial product's trade
   dress carries risk that this plan cannot assess. The owner should decide whether the route stays
   unpublished or private for evaluation.
3. **Window basis.** Recommend evaluating fidelity in standalone/full-screen mode, because the
   browser URL bar changes the bucket (F12).
4. **Default font.** Accept a labelled substitute for TT Norms Pro, or buy a web licence (no spending
   without approval).
5. **Device evidence.** A `CR` rating needs captures from the owner's phone. Without them, the plan
   delivers static conformance only and reports so.
