# Ordinary Relay deployment draft

This draft pairs deployment base `4c18a226e10968437941d82b77c3c09383815898`
with source `ccf1064764ba00451864023f494a0204564b1478`. The source retains
the live configuration, dependencies, Poweramp, Astra, MyMedia and Podcasts.
Its ordinary Relay backend changes need the existing fresh Worker qualification
and publication path. No account-admission, native dispatch, preflight or
profile-pricing subsystem is included or required.

The original client-only identity entrypoint and its refusal diagnostics remain
unchanged. The workflow uses `relay-worker-release-identity.mjs` for this full
release. Its explicit release policy binds all fourteen recipe blobs, file
modes, the release metadata, exact source checkout and native backend closure
to the same immutable orchestration HEAD before provider reads. Only the
original successful production provenance checks can establish Worker reuse.
A missing or refused reuse proof requests the existing qualified deployment;
a live provider identity refusal emits no deployment flag or checkpoint.
Recording a fresh deployment requires its uniquely uploaded active version
and unchanged settings. Promotion rechecks the exact candidate and current
Worker identity.

All original qualification, configuration, namespace, rollback backup,
staged-byte, live API, mobile podcast and production-receipt checks remain.
The changed recipe deliberately retains full current qualification rather
than extending the historical main-push dedup fingerprint. All eight source lanes
require current qualification through verified eligible reuse or fresh execution,
plus a sealed artifact. Trusted source-main evidence supports eligible reuse;
it is not a separate prerequisite for the fresh publication path.

After the existing full backup and rollback artifact barriers, the dependency
helper verifies the complete configured seal and stages four fixed modules:
`relay-transfer.js`, `relay-draft-store.js`, `public-coordination.js`, then
`public-reader-cache.js`. Each upload must be followed by a successful GET with
the exact JavaScript MIME, byte length and SHA-256 before any importer is
overwritten. Four uploads and four verification reads are permitted, each with
the existing thirty-second bound and no automatic retries. The unordered later
batch excludes all four modules. A missing module, byte or seal drift, refusal,
interruption or lost response stops before that batch.

Historical c85 tests keep their existing assertions using the exact archived
release and recipes and a genuine temporary c85 source worktree. The build
checkout now retains source history, as the plan and component checkouts
already do. These offline fixtures neither invent a source SHA nor attest a
live provider, storage backup, hosted artifact or production execution.

Local tests and builds prepare a reviewable draft. Exact hosted qualification,
independent review and existing live gates
are still required before promotion. No local check authorizes deployment.
